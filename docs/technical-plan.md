# 贪吃蛇游戏 MVP 技术方案

## 目标与范围

依据 [产品设计](product-design.md)，实现打开浏览器即可玩的单人贪吃蛇游戏。首版支持电脑键盘、固定棋盘和速度，以及开始、暂停、继续、结束、胜利和重开流程。

首版采用纯前端静态网页，不引入后端、数据库或账号系统。移动端触控、难度选择、音效、皮肤、排行榜和最高分保存不属于本次实现范围。

## 技术栈

| 技术 | 用途 |
| --- | --- |
| TypeScript | 游戏规则、状态管理、键盘输入和页面控制 |
| Vite（vanilla-ts 模板） | 开发服务和生产构建 |
| Canvas 2D | 绘制网格、蛇和食物 |
| 原生 HTML/CSS | 标题、分数、状态提示、按钮和操作说明 |
| Vitest | 游戏规则和状态变化的单元测试 |
| Playwright | 浏览器操作和完整流程测试 |
| npm | 依赖管理和统一执行命令 |

开发环境使用满足所选 Vite、Vitest 版本要求的 Node.js LTS。初始化时确认版本兼容性，提交 package-lock.json，后续使用 npm ci 安装锁定的依赖。

## 代码组织

建议按职责划分为以下文件，无需引入 UI 框架或游戏引擎：

```text
index.html                  页面入口
src/main.ts                 初始化、按钮事件和游戏循环
src/game/types.ts           坐标、方向、游戏状态类型
src/game/config.ts          棋盘、速度和初始蛇配置
src/game/engine.ts          状态初始化、移动、碰撞和食物生成
src/input.ts                键盘映射与待执行方向管理
src/render.ts               Canvas 绘制与页面信息更新
src/style.css               页面样式
tests/unit/                 Vitest 测试
tests/e2e/                  Playwright 测试
```

游戏引擎不依赖 DOM、Canvas 或定时器。它接收状态、方向和可注入的随机数函数，返回下一步状态；页面层负责输入、时间推进和渲染。这样规则可以脱离浏览器进行确定性测试。

## 状态与关键规则

游戏状态包含蛇的坐标列表（蛇头在前）、当前方向、食物坐标、本局分数和阶段。阶段为 ready、running、paused、gameOver、won；胜利时食物为 null。

默认配置建议为 30 × 30 网格、每 200 毫秒移动一格，初始蛇长 3 格，位于棋盘中央并朝右。尺寸与速度集中在配置中，首版不向玩家提供调整入口。这些参数是实现默认值，可在体验验证时调整。

- **开始与重开：** 使用同一个初始化函数生成新局，重置蛇、方向、食物、分数、待执行输入和计时状态；新局进入 running。初次打开页面处于 ready，不自动移动。
- **转向：** 支持方向键和 WASD。每个移动周期最多接受一次有效转向，按实际移动方向拒绝反向；无效输入不占用该周期的转向机会。移动执行后清空待执行方向，避免连续按键在一次移动前绕过反向限制。
- **移动与碰撞：** 先计算下一格和是否吃食物，再判断越界或自身碰撞。未吃食物时尾部本步会移走，碰撞检查排除该尾格；吃食物时保留尾部。合法移动后更新蛇身。
- **增长与食物：** 吃食物后增加一格和 1 分。枚举所有空格，再随机选择其中一格作为食物，避免随机重试在棋盘接近填满时变慢。
- **胜利：** 增长后先检查是否填满棋盘，满盘直接进入 won，清空食物，不再生成食物。
- **暂停与结束：** 只有 running 可以推进移动。暂停保留棋盘和分数，清空待执行转向；paused、gameOver 和 won 阶段忽略方向输入。空格和暂停按钮只在 running、paused 之间切换。

## 时间、输入与画面

使用单一 setInterval 按固定周期推进游戏，每次合法状态变化后重绘。暂停、结束和胜利时停止定时器；继续或重开时先清理旧定时器，再启动一个新定时器。继续后等待完整的一个移动周期，不补算暂停期间的移动。

键盘事件统一处理，忽略自动重复的 keydown，避免长按空格连续切换暂停。对游戏控制键阻止页面滚动，并避免空格在按钮获得焦点时同时触发按钮默认行为和全局暂停逻辑。

Canvas 使用网格坐标转换为像素坐标，并根据 devicePixelRatio 设置实际绘制尺寸，以保持画面清晰。蛇头、蛇身和食物使用易于区分的样式。分数、当前状态和最终分数使用 HTML 文本展示，按钮根据阶段显示适用操作。

## 测试与验收

### 单元测试（Vitest）

覆盖产品文档的规则边界，并通过注入随机数、构造状态和模拟时钟消除随机性与实际等待：

| 场景 | 预期结果 |
| --- | --- |
| 初始化与重开 | 初始蛇、方向、分数和阶段正确；输入与计时状态清空 |
| 普通移动与吃食物 | 普通移动长度不变；吃食物增长一格且加 1 分 |
| 反向与快速连续输入 | 直接反向被拒绝；同周期多次输入不能绕过限制 |
| 撞墙与撞身体 | 进入 gameOver，后续时间推进不再移动 |
| 移动到即将移走的尾格 | 允许合法移动，不误判自身碰撞 |
| 食物生成 | 始终落在空格；仅剩一个空格时仍能正确生成 |
| 填满棋盘 | 进入 won，食物为 null，不调用食物生成逻辑 |
| 暂停与继续 | 暂停时状态不变；继续后按完整周期恢复移动 |
| 反复暂停或重开 | 始终只有一个有效定时器，无额外移动 |

### 浏览器测试（Playwright）

验证首次进入不自动开始、点击开始、方向键与 WASD、空格与按钮暂停、继续、结束提示和重开。检查分数和状态文本、暂停时棋盘保持不变，以及控制键不导致页面滚动。

吃食物、尾部碰撞和胜利等难以通过随机游戏稳定复现的场景，以单元测试覆盖规则，并通过仅在测试环境启用的确定性场景验证浏览器反馈；测试入口不进入生产构建。至少在 Chromium 中自动验证，在交付前检查桌面 Firefox 和 WebKit 的操作兼容性。

### 交付检查

实现阶段提供统一命令：npm run typecheck、npm run test、npm run test:e2e 和 npm run build。每次改动更新相关测试，所有测试、类型检查和构建通过后创建对应 Git commit；浏览器验证确认画面、键盘和完整流程符合产品设计。

本技术方案的文档验证记录见 [方案检查清单](technical-plan-checklist.md)。

## 实现顺序与部署

1. 建立 Vite、TypeScript 和测试基础，完成游戏引擎及规则测试。
2. 接入 Canvas、键盘和游戏循环，实现全部状态与页面操作。
3. 补齐浏览器测试，完成操作体验、兼容性和生产构建验证。

生产构建输出 dist 目录，部署到静态网站托管服务即可；部署时按托管路径配置 Vite base。后续最高分本地保存可以增加 localStorage，在线排行榜再单独规划服务端。
